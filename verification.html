Public verification portal

Phase 20. This page explains how a reader can independently check what this presentation site claims to list. It does not invent hashes, timestamps, or judicial findings.

A file on GitHub is not, by itself, a blockchain proof or a court verdict. Only commit history, public paths, and any SHA values that can actually be shown should be treated as inspectable. This rebuild has not calculated PDF content hashes and has not invented verification records.

What you can verify

  1. Public path — open the raw or tree URL on GitHub and confirm the file exists under that path.
  2. Commit history — inspect when a path was added or changed in the source repository.
  3. Catalogue ID — match DOC-, MED-, EVT-, PUB- rows on this site to the linked path.
  4. Evidence-status label — read whether a row is labelled Official record (document title), Author’s Account, Allegation, Filename date only, etc.
  5. External listings — for books or profiles, open the publisher or platform page cited (e.g. Apple Books, The Conversation) and compare titles.

What this site does not claim

  • That every allegation in a filename or testimony is established.
  • That a download proves wrongdoing.
  • That blockchain_manifest.json proves the contents of every PDF.
  • That this presentation layer has independently re-hashed every binary.
  • That inclusion of a person or organisation establishes liability.

Evidence-status vocabulary

Status labels used across the archive include (among others):

  • JUDICIALLY ESTABLISHED / OFFICIALLY DETERMINED — only when an authoritative determination is cited
  • OFFICIAL RECORD / PRIMARY SOURCE — often from document title or folder listing
  • AUTHOR’S ACCOUNT / ALLEGATION / INTERPRETATION
  • FILENAME DATE ONLY / FILENAME / PUBLIC PATH
  • UNVERIFIED / DISPUTED / RESEARCH QUESTION / UNKNOWN

Full enums: DATA-MODEL.md · EVIDENCE-STANDARDS.md · LEGAL-CAUTION.md

How to check one catalogue row

  1. Open Document database or Media archive.
  2. Note the ID (e.g. DOC-0001) and original_path.
  3. Click Open / Download to the GitHub raw URL, or browse the tree path.
  4. Optionally open the repository’s History for that file on GitHub.
  5. Read the evidence-status and privacy flags on the catalogue row; do not upgrade them without independent authority.
